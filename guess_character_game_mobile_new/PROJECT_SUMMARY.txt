1. 项目概述
================================================================================

这是一个基于Flutter开发的Android/iOS手机游戏，主题是Project SEKAI
（世界计划 / プロセカ）的猜谜游戏。软件包含三个游戏模式：

  (1) 猜卡面：显示一张卡牌图片的局部碎片，玩家猜这张卡属于哪个角色。
  (2) 猜MV：播放一段B站MV视频片段（静音+背景音乐），玩家猜歌曲名。
  (3) 猜音乐：播放一段音乐音频片段，玩家猜歌曲名。

软件启动时会自动从网站 pjsk.moe 检查并下载新卡牌和新歌曲数据，
增量更新到本地，无需手动操作。

游戏资源（卡牌图片、音乐音频、MV视频）全部来自外部网站，
软件本身只存储数据索引和元信息，不内置图片/音频/视频资源。

4. 数据来源详解（外部网站/API）
================================================================================

【重要】所有游戏资源来自以下外部网站，软件本身不内置图片/音频/视频。

4.1 卡牌图片资源
    服务器：https://storage.exmeaning.com/sekai-jp-assets/
    路径格式：
      特训前：/character/member/{resNum_noNum}/card_normal.webp
      特训后：/character/member/{resNum_noNum}/card_after_training.webp
    示例：
      https://storage.exmeaning.com/sekai-jp-assets/character/member/res001_no003/card_normal.webp
    说明：resNum是3位数字（如001=星乃一歌），noNum是3位数字（卡牌序号）
         resNum与角色的对应关系见 game_service.dart 第14-41行 RES_TO_CHARACTER 映射表

4.2 卡牌详情页面（用于扫描新卡）
    网站：https://pjsk.moe/ja-JP/cards/{id}/
    说明：id是数字（如1422），日服路径用 ja-JP
    判断卡牌有效性的方法：
      - 页面标题不能是 "カード詳細 | Moesekai"（无效卡牌的占位标题）
      - og:image 不能是通用图标 pjsk.moe/data/icon/icon.jpg
      - 从 og:image URL 中提取 res{数字}_no{数字} 获取资源ID和角色

4.3 音乐封面资源
    服务器：https://storage.exmeaning.com/sekai-jp-assets/
    路径格式：/music/jacket/jacket_s_{id}/jacket_s_{id}.webp
    示例：https://storage.exmeaning.com/sekai-jp-assets/music/jacket/jacket_s_001/jacket_s_001.webp

4.4 音乐音频资源
    服务器：https://storage.exmeaning.com/sekai-jp-assets/
    路径格式：/music/long/{prefix}_{id4}_{suffix}/{prefix}_{id4}_{suffix}.mp3
    参数说明：
      prefix = 版本前缀（2字母）
        vs = バーチャル・シンガーver.（虚拟歌手版）
        se = セカイver.（中之人版）
        （旧代码还检查 in/an/so/ba/li/og/re/et/co/pm/fu 共13种，现已精简为2种）
      id4 = 4位数字的歌曲ID（如 0001, 0758）
      suffix = 2位数字的版本序号（新歌只检查 01）
    示例：https://storage.exmeaning.com/sekai-jp-assets/music/long/vs_0001_01/vs_0001_01.mp3
    说明：新歌最多只有 vs（虚拟歌手）和 se（セカイ）两个版本，各只有 suffix 01

4.5 音乐详情页面（用于扫描新歌）
    网站：https://pjsk.moe/ja-jp/music/{id}/
    说明：从 og:title 元标签提取歌曲标题

4.6 网站地图（用于获取歌曲ID列表）
    入口：https://pjsk.moe/sitemap.xml
    详细地图：https://pjsk.moe/sitemap-details/ja-jp.xml
    说明：从详细地图中用正则提取所有 /ja-jp/music/(\d+)/ 获取歌曲ID

4.7 B站MV视频（猜MV模块）
    视频信息API：https://api.bilibili.com/x/web-interface/view?bvid={bvid}
      → 返回视频信息，从中提取 cid
    视频下载URL API：https://api.bilibili.com/x/player/playurl?bvid={bvid}&cid={cid}&qn=64
      → 返回可下载的视频URL
    下载请求头需要：
      User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
      Referer: https://www.bilibili.com/
    说明：bvid是B站视频ID（如 BV1xwx1e8E16），存储在 mv_videos_matched.json 中

6.1 数据服务：game_service.dart
    文件：D:\Trae CN\program\game\guess_character_game_mobile_new\lib\game_service.dart

    【类结构】
    - CardData：卡牌数据类

      内部数据：
        _allCards：所有卡牌列表
        _validCards：有效卡牌列表（仅3星、4星、生日卡，用于猜卡抽取）

    【卡牌加载流程】（loadCards方法，第70-101行）
      (1) _loadCardsFromJson()：从 assets/data/cards.json 加载基础卡牌
      (2) _loadExtraCardsFromJson()：从 assets/data/extra_cards.json 加载额外卡牌
      (3) _loadNewCardsFromPrefs()：从 SharedPreferences 加载之前扫描到的新卡
      (4) 按ID数字排序

    【卡牌更新流程】（checkForCardUpdatesInBackground方法，第131-219行）
      (1) 读取 SharedPreferences 中保存的最后卡牌ID（PREFS_KEY_LAST_CARD_ID，默认1421）
      (2) 从 lastCardId + 1 开始逐个检查ID
      (3) 对每个ID，调用 _fetchCardData() 获取卡牌信息
      (4) 连续5个ID无效则停止扫描
      (5) 新卡添加到 _allCards 和 _validCards（仅3星以上/生日卡）
      (6) 保存新卡到 SharedPreferences，更新最后卡牌ID

    【_fetchCardData方法】（第228-461行）- 从网站获取单张卡牌信息
      (1) 请求 https://pjsk.moe/ja-JP/cards/{id}/
      (2) 检查页面标题，如果是"カード詳細 | Moesekai"则无效
      (3) 检查og:image，如果是通用图标则无效
      (4) 从og:image URL提取 res{数字}_no{数字} 获取资源ID
      (5) 通过 RES_TO_CHARACTER 映射表获取角色名
      (6) 构建图片URL：
          normalUrl = https://storage.exmeaning.com/sekai-jp-assets/character/member/{resId}/card_normal.webp
          afterUrl  = .../card_after_training.webp
      (7) 解析稀有度：依次尝试 ★格式、星格式、rarity-N class格式、birthday关键词
          如果都失败，默认设为3
      (8) 从 CARD_NAMES 映射表或页面标题获取卡牌名称

    【重要常量】
    - CARD_BASE_URL = 'https://storage.exmeaning.com/sekai-jp-assets/character/member'
    - PREFS_KEY_LAST_CARD_ID = 'last_card_id'（默认值1421）
    - PREFS_KEY_NEW_CARDS = 'new_cards_data'
    - RES_TO_CHARACTER：resNum(3位) → 角色名 的映射（001-026，共26个角色）

7.1 数据服务：music_game_service.dart

    【类结构】

            aliases（别名列表）、audioUrls（音频URL列表）、versionNames（版本名列表）、

    - MusicGameService：音乐服务（非单例，每次new）
      内部数据：

        _recentPlayedIds：最近播放的歌曲ID集合（最多50个，避免重复抽取）

    【重要常量】（第11-13行）
    - AUDIO_BASE_URL = 'https://storage.exmeaning.com/sekai-jp-assets/music/long'
    - JACKET_BASE_URL = 'https://storage.exmeaning.com/sekai-jp-assets/music/jacket'
    - MUSIC_LIST_URL = 'https://pjsk.moe/ja-jp/music/'

    【音乐加载流程】（loadMusics方法，第132-144行）
      (1) _loadMusicsFromLocal()：从本地文件加载
          - 优先读取 应用文档目录/musics_full_updated.json（更新后的文件）
          - 回退到 assets/data/musics_full.json（内置文件）
      (2) 如果本地有数据：assignCategories() 分配分类 + _checkForUpdatesInBackground() 检查更新
      (3) 如果本地无数据：_loadMusicsFromPjskMoe() 首次从网站全量加载

    【音乐更新流程】（_checkForUpdatesInBackground方法，第171-294行）
      (1) 请求 https://pjsk.moe/sitemap.xml
      (2) 从中提取 https://pjsk.moe/sitemap-details/ja-jp.xml
      (3) 请求详细地图，用正则提取所有歌曲ID
          正则：<loc>https://pjsk\.moe/(?:ja-jp/)?music/(\d+)/</loc>
      (4) 按ID降序排列
      (5) 读取 SharedPreferences 中的 last_saved_music_id（默认754）
      (6) 从最大ID开始往下扫描，遇到 last_saved_music_id 则停止
      (7) 对每个新ID调用 _fetchMusicData() 获取歌曲信息
      (8) 新歌添加到 _musics，保存到本地文件，更新 last_saved_music_id

    【_fetchMusicData方法】（第363-456行）- 从网站获取单首歌曲信息
      (1) 检查封面是否存在：HEAD请求 jacket_s_{id}/jacket_s_{id}.webp
      (2) 请求 https://pjsk.moe/ja-jp/music/{id}/
      (3) 从 og:title 元标签提取歌曲标题
      (4) 检查音频版本（只检查2种，各1个suffix）：
          - vs_{id4}_01（バーチャル・シンガーver.）
          - se_{id4}_01（セカイver.）
      (5) 至少有1个音频版本才认为是有效歌曲
      (6) id4 = id左补零到4位（如 1 → 0001, 758 → 0758）

    【首次全量加载】（_loadMusicsFromPjskMoe方法，第303-350行）
      按7个分类逐个获取：vocaloid, light_music_club, idol, street,
      theme_park, school_refusal, other
      请求 https://pjsk.moe/ja-jp/music/?tag={category}
      从HTML中提取 /ja-jp/music/(\d+)/ 获取歌曲ID

    【分类分配】（assignCategories方法，第524-551行）
      从 assets/data/music_categories.json 读取分类映射

12. 已知问题与注意事项
================================================================================

12.1 卡牌稀有度解析
    - 网站页面格式可能变化，稀有度解析依赖多种正则：
      ★格式、星格式、rarity-N class格式、birthday关键词
    - 如果所有解析都失败，默认设为3星
    - 二星卡会被排除在猜卡池外（_validCards只包含3星以上和生日卡）

12.2 音乐扫描速度
    - 每首新歌需要检查2个音频URL是否存在（vs和se版本）
    - 每个检查是一次HTTP请求，受网络延迟影响
    - 网站没有提供音频列表API，只能逐个探测

12.3 网站URL格式
    - 网站使用Next.js框架，URL带语言前缀：/ja-jp/（日服）、/zh-cn/（国服）
    - 本软件只使用日服数据（/ja-jp/）
    - sitemap结构：sitemap.xml → sitemap-details/ja-jp.xml
    - 如果网站结构再次变更，需要更新正则表达式

12.4 B站视频下载
    - 依赖B站API，可能因B站反爬或API变更导致下载失败
    - 下载失败会自动尝试下一个视频
    - 视频质量qn=64（720P）

12.5 SharedPreferences 存储限制
    - 'new_cards_data' 存储所有卡牌数据，随着卡牌增加可能接近上限（约5MB）
    - 如果超限可能需要改用文件存储

12.6 两个 musics_full 文件
    - assets/data/musics_full.json 和 musics_full_updated.json 内容相同
    - 运行时更新的文件保存在应用文档目录，不在assets中

12.7 卡牌图片URL拼接
    - 卡牌图片URL通过规则拼接，不直接存储完整URL
    - 规则：https://storage.exmeaning.com/sekai-jp-assets/character/member/{resId}/card_normal.webp
    - resId 格式：res{3位数字}_no{3位数字}（如 res001_no003）
